# Prometheus + Grafana + Alertmanager Monitoring Stack

A Docker Compose monitoring and alerting stack built with Prometheus, Grafana, Node Exporter, and Alertmanager.

This project extends a basic Prometheus + Grafana monitoring setup by adding alerting capabilities through Prometheus alert rules and Alertmanager.

## Components

### Prometheus

Prometheus collects and stores metrics from Node Exporter and evaluates alert rules.

Default port: 9090

### Grafana

Grafana connects to Prometheus and provides dashboards for visualizing system metrics.

Default port: 3000

### Node Exporter

Node Exporter exposes Linux system metrics such as CPU, memory, disk, and network statistics.

Default port: 9100

### Alertmanager

Alertmanager receives alerts generated by Prometheus and manages the alerts.

Default port: 9093

## Prometheus Configuration

Prometheus collects metrics from:

    prometheus:9090
    node-exporter:9100

Alert rules are loaded from:

    /etc/prometheus/alert-rules.yml

Prometheus sends firing alerts to Alertmanager at:

    alertmanager:9093

Docker Compose service names are used for communication between containers.

## Alert Rules

### Node Exporter Down

This alert fires when Node Exporter becomes unavailable for more than 30 seconds:

    - alert: NodeExporterDown
      expr: up{job="node-exporter"} == 0
      for: 30s
      labels:
        severity: critical
      annotations:
        summary: "Node Exporter is down"
        description: "Node Exporter has been unavailable for more than 30 seconds."

### High CPU Usage

This alert fires when CPU usage remains above 80% for more than one minute:

    - alert: HighCPUUsage
      expr: 100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
      for: 1m
      labels:
        severity: warning
      annotations:
        summary: "High CPU usage"
        description: "CPU usage has been above 80% for more than 1 minute."

## Grafana Dashboard

Grafana uses Prometheus as its data source to visualize system metrics.

### CPU Usage

    100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

### Memory Usage

    100 * (1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes))

### Disk Usage

    100 * (1 - (node_filesystem_avail_bytes{fstype!~"tmpfs|overlay"} / node_filesystem_size_bytes{fstype!~"tmpfs|overlay"}))

## Testing the Alert System

### Test 1 — Node Exporter Failure

Stop Node Exporter:

    sudo docker stop node-exporter

Wait approximately 30 seconds and check:

    http://localhost:9090/alerts

The NodeExporterDown alert should become:

    FIRING

Check Alertmanager:

    http://localhost:9093

The alert should also appear there.

Start Node Exporter again:

    sudo docker start node-exporter

The alert should eventually become resolved.

### Test 2 — High CPU Usage

Generate CPU load:

    yes > /dev/null &

If necessary, run multiple processes:

    yes > /dev/null &
    yes > /dev/null &
    yes > /dev/null &
    yes > /dev/null &

Monitor CPU usage:

    top

After CPU usage remains above 80% for approximately one minute, check:

    http://localhost:9090/alerts

The HighCPUUsage alert should become:

    FIRING

After testing, stop the CPU load:

    killall yes

The alert should eventually become resolved.
